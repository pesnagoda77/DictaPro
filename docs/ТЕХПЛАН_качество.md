# ТЕХПЛАН КАЧЕСТВА DictaPro — как уйти от «унылого говна»

Дата: 14.09.2026 · Автор: Claude

## Ключевая мысль
Качество расшифровки = **движок + обработка звука ДО + обработка текста ПОСЛЕ**.
Мы всё время меняли только движок (VOSK→whisper→sherpa). Два других слоя — почти не трогали,
а они дают сопоставимый прирост. Всё ниже — ЛОКАЛЬНОЕ (правило: офлайн по умолчанию).

## Слой 1. Обработка звука ДО распознавания (недоиспользован!)
Записи уличные/домашние с ТВ, шумом, эхом — отсюда половина ошибок.
| Метод | Что даёт | Стоимость/риск |
|---|---|---|
| **DeepFilterNet** (ONNX, офлайн) | Шумоподавление уровня студии, +10-20% к WER на шумных записях | Средняя интеграция (ONNX/FFI), ~20 МБ модель |
| **RNNoise** (C, крошечный) | Хорошее подавление стационарного шума (ТВ, гул) | Легко (FFI), ~1 МБ |
| **Silero VAD** (ONNX, ~2 МБ) | Режет тишину/шум перед распознаванием: быстрее + точнее | Легко |
| **AGC + фильтр высоких/низких** | Выравнивает тихую речь | Тривиально |
| Запись 48 кГц + качественный ресемпл в 16 кГц | Меньше «каши» на входе | Тривиально |

## Слой 2. Движок распознавания (главный, но не единственный)
| Кандидат | WER (RU) | Размер | Статус |
|---|---|---|---|
| **Sherpa-ONNX + GigaAM CTC v2** | ~4.5% (по нашему июньскому исследованию!) | 226 МБ | Прототип P1 (FFI) |
| whisper.cpp base/small (из исходников, GGML_CPU_ALL_VARIANTS) | ~8-14% | 60-500 МБ | Прототип P2 |
| VOSK малая (сейчас) | ~50% на его записях | 45 МБ | Заменить |
| VOSK большая | ~18% | 1.8 ГБ | Отклонена |

## Слой 3. Обработка текста ПОСЛЕ (локально!)
| Метод | Что чинит | Статус |
|---|---|---|
| Числительные → цифры (парсер) | «восемьдесят восемь целых шесть десятых процента» → «88,6%» | ТЗ 016 (Итан) |
| Локальная пунктуация (улучшить rule-based; возможна маленькая ONNX-модель пунктуации) | Расстановка запятых/точек | Часть 016 |
| **Локальная LLM-коррекция** (Gemma 3 1B / Qwen2.5-0.5B / SmolLM2-360M, ONNX/MediaPipe) | Термины, имена, явные ошибки по контексту — БЕЗ облака | Новый слой (идея из их же июня: Gemma 3 1B) |
| Пользовательские горячие слова (VOSK/GigaAM) | Имена/термины под тему записи | Часть 016 |
| Подсветка неуверенных слов (confidence) | Пользователь сам правит | Часть 016 |

## Порядок работ (по влиянию на результат/затратам)
1. **P1: движок GigaAM через sherpa-onnx** — самый большой скачок (WER 50%→~5-15%). Рецепт от Кими, прототип — Итан.
2. **Простая предобработка**: VAD (Silero) + AGC + 48кГц — быстро, заметно на шумных записях.
3. **Локальная чистка текста** (016) — числа/пунктуация/горячие слова.
4. **DeepFilterNet/RNNoise** — если после 1-3 ещё будут жалобы на шум.
5. **Локальная LLM-коррекция** (маленькая модель на ONNX) — финальный лоск, полностью офлайн.
6. **P2 (whisper из исходников)** — как альтернатива движка, если P1 не взлетит.

## Критерии «не унылое говно» (измеримо)
- WER на РЕАЛЬНЫХ записях Славана (набор из 10 записей: тихая комната, ТВ, улица, телефонный звонок) ≤ 15% — цель; текущий VOSK ~50%.
- Числа и проценты — цифрами, читаемо в деловом тексте.
- Имена/термины его темы распознаются при внесённых горячих словах.
- Ни одного падения на vivo V2247; час аудио обрабатывается ≤20-30 мин в фоне.
Все проверки — на ОДНОМ И ТОМ ЖЕ наборе записей, чтобы сравнивать честно.
