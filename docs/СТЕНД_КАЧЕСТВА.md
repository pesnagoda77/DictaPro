# СТЕНД КАЧЕСТВА DictaPro — как измеряем движок объективно

Дата: 14.09.2026 · Автор: Claude

## Зачем
Слова «лучше/хуже» не считаются. Бенчмарк даёт цифру: **WER** (доля ошибок слов)
на РЕАЛЬНЫХ записях Славана. Один и тот же стенд прогоняем для каждого движка.

## Базовое число (VOSK small, 14.09.2026)
| Тест | Эталон | Распознано | **WER** |
|---|---|---|---|
| Текст про кормовые жиры (чтение вслух ~10 мин) | 985 слов | 1155 слов | **66.1%** (651 ошибка) |

Примеры ошибок VOSK: «зооинженер, ветврач» → «зао инженер вет врач»; числа словами
(«1» → «первая»); падежи («должны» → «должна»); «при формировании контентной» →
«переформирование контент на».

## Как измерять (инструмент готов)
```
python tools/wer_bench.py <эталон.txt> <гипотеза.txt>
```
Нормализация: регистр, ё→е, пунктуация; числа-слова НЕ приводятся (их ошибочность —
часть оценки!). Показывает WER + примеры расхождений.

## Набор тестов (как пополнять)
Нужно 4-6 пар «эталон-текст / запись»:
1. **Тихая комната** (чтение делового текста) — есть ✓ (текущий тест)
2. **С работающим ТВ** (шум)
3. **Улица/шумное место**
4. **Телефонный звонок** (узкополосная речь)
5. **Спонтанная речь** (не чтение, свободная диктовка)
Каждая пара: эталон = текст, который читался/говорился; гипотеза = транскрипт приложения.

## Критерии приёмки движка
| Метрика | Цель |
|---|---|
| WER на наборе (средневзвешенный) | **≤ 15%** (у VOSK сейчас 66%) |
| Числа | цифрами, читаемо |
| Падения на vivo V2247 | 0 |
| RTF (скорость) | ≤ 0.6 → час аудио ≤ 36 мин в фоне |
| Пик RAM | ≤ 600 МБ |
| Размер модели | ≤ 300 МБ (иначе не качают) |

## План прогонов
- VOSK (текущий): 66.1% — зафиксировано.
- **GigaAM v3 через sherpa_ONNX** (ТЗ 017): ожидание ≤15%; прогон после сборки.
- Whisper-из-исходников (если понадобится): прогноз хуже GigaAM и медленнее.

## 2026-09-15 — ПРИЁМКА GigaAM v3 (Redmi Note 10S, Android 11)
- Запись: 11 мин 08 с, 16 кГц моно (case1, тихая комната). Эталон: 985 слов.
- **VOSK (старый движок): WER 66,1%** (воспроизведено стендом, совпадает с базой).
- **GigaAM v3 int8 (новый): WER 25,6%** (1004 слова, 252 ошибки) — **ошибок в 2,6 раза меньше**.
- Скорость: 11 мин расшифровано менее чем за 3 мин → RTF ≈ 0,25 (цель ≤0,6) — запас двукратный.
- Вылет на длинных записях устранён (был Ort::Exception в ONNX Runtime на слишком длинном куске; теперь режем на 10 с).
- Наблюдения для улучшения: (1) резать по паузам, а не вслепую каждые 10 с — на стыках теряются слова (~до 5-7 п.п. WER); (2) в тексте приложение добавляет префикс «Speaker 1:» в каждой строке — мешает и экспорту, и подсчёту (убрать при одном спикере); (3) чистый микрофон/близкая диктовка дадут заметно лучше.
- Скрипт стенда: docs/tools/wer_bench.py; данные: docs/bench/case1_tihaya_komnata/.

## 2026-09-15 (продолжение) — подбор параметров нарезки (локальный прогон, 6 вариантов)
Запись та же (case1, 11 мин 08 с, 985 слов эталона). Движок GigaAM v3 int8, feature_dim=64, greedy.
| Вариант | WER | Время на 11 мин |
|---|---|---|
| VOSK (база) | 66,1% | — |
| куски 60 с | 24,2% | 110 с |
| куски 10 с | 23,5% | 53 с |
| куски 30 с | 20,8% | 54 с |
| VAD textback; паузы 0,5 с, кусок 10 с | 20,4% | 59 с |
| **VAD: паузы ≥0,8 с, кусок ≤20 с — ПОБЕДИТЕЛЬ** | **18,9%** | 60 с |
| VAD: паузы 0,8 с, кусок 30 с | 19,7% | 62 с |
Выводы: (1) модель держит куски до 60 с без вылета (крах был на 166 с); (2) мелкая нарезка вредит; (3) перехлёст+склейка по тексту добавляют лишние слова — отключены; (4) в приложение перенесены: minSilenceDuration 0,8 с, maxSpeechDuration 20 с, пауза-ориентированный разрез (без перехлёста).
