# СТЕНД КАЧЕСТВА DictaPro — как измеряем движок объективно

Дата: 14.09.2026 · Автор: Claude

## Зачем
Слова «лучше/хуже» не считаются. Бенчмарк даёт цифру: **WER** (доля ошибок слов)
на РЕАЛЬНЫХ записях Славана. Один и тот же стенд прогоняем для каждого движка.

## Базовое число (VOSK small, 14.09.2026)
| Тест | Эталон | Распознано | **WER** |
|---|---|---|---|
| Текст про кормовые жиры (чтение вслух ~10 мин) | 985 слов | 1155 слов | **66.1%** (651 ошибка) |

Примеры ошибок VOSK: «зооинженер, ветврач» → «зао инженер вет врач»; числа словами
(«1» → «первая»); падежи («должны» → «должна»); «при формировании контентной» →
«переформирование контент на».

## Как измерять (инструмент готов)
```
python tools/wer_bench.py <эталон.txt> <гипотеза.txt>
```
Нормализация: регистр, ё→е, пунктуация; числа-слова НЕ приводятся (их ошибочность —
часть оценки!). Показывает WER + примеры расхождений.

## Набор тестов (как пополнять)
Нужно 4-6 пар «эталон-текст / запись»:
1. **Тихая комната** (чтение делового текста) — есть ✓ (текущий тест)
2. **С работающим ТВ** (шум)
3. **Улица/шумное место**
4. **Телефонный звонок** (узкополосная речь)
5. **Спонтанная речь** (не чтение, свободная диктовка)
Каждая пара: эталон = текст, который читался/говорился; гипотеза = транскрипт приложения.

## Критерии приёмки движка
| Метрика | Цель |
|---|---|
| WER на наборе (средневзвешенный) | **≤ 15%** (у VOSK сейчас 66%) |
| Числа | цифрами, читаемо |
| Падения на vivo V2247 | 0 |
| RTF (скорость) | ≤ 0.6 → час аудио ≤ 36 мин в фоне |
| Пик RAM | ≤ 600 МБ |
| Размер модели | ≤ 300 МБ (иначе не качают) |

## План прогонов
- VOSK (текущий): 66.1% — зафиксировано.
- **GigaAM v3 через sherpa_ONNX** (ТЗ 017): ожидание ≤15%; прогон после сборки.
- Whisper-из-исходников (если понадобится): прогноз хуже GigaAM и медленнее.
