# ПЛАН: системная перепроверка офлайн-движков DictaPro (без зацикленности)

Дата: 14.09.2026 · Автор: Claude · Утвердил: Славан

## Принцип
Все прошлые попытки провалились НЕ потому, что «это невозможно», а потому что мы
повторяли один и тот же путь вслепую. Здесь: для КАЖДОГО провала — анализ корневой причины
и КОРРЕКТНЫЙ способ повторить. Проверяем на живом устройстве (vivo V2247), без иллюзий.

## Разбор провалов (что реально произошло)

### Провал 1: whisper.cpp (6 попыток, SIGILL)
- **Что делали:** ставили готовые пакеты (whisper_flutter_new, whisper_ggml, whisper_kit,
  flutter_whisper_ffi, sherpa_onnx-без-обвязки) и запускали.
- **Факт:** `SIGILL` на vivo V2247 — процессор не понимает инструкцию.
- **Корневая причина (гипотеза, подтвердить):** в prebuilt-библиотеках собраны варианты
  с инструкциями ARMv8.2+ (i8mm/dotprod), которых нет в CPU устройства; ggml выбирает
  вариант по флагам сборки, а не по возможностям процессора.
- **Правильный путь:** собрать whisper.cpp ИЗ ИСХОДНИКОВ через NDK с
  `GGML_CPU_ALL_VARIANTS=ON` (runtime-диспетчеризация по CPU) ИЛИ принудительный baseline
  (только NEON). Тогда SIGILL исчезает. Отдельно: правильная версия NDK (21-22, не 26).
- **Ожидание:** base/tiny q5 → на телефоне реально (RAM ~0.9 ГБ small, base меньше).

### Провал 2: sherpa-onnx (+GigaAM) — «нет обвязки для Flutter»
- **Что решили в июне:** sherpa_onnx «только C++/Python/Go» → отложили. НО исследование
  июня же назвало **Sherpa-ONNX + GigaAM CTC v2 лучшим вариантом: 226 МБ, WER ~4.5%**
  (снижение ошибок на 54% против VOSK).
- **Корневая причина «провала»:** не техническая невозможность, а отсутствие готовой
  Flutter-обёртки. У sherpa-onnx ЕСТЬ C API и Android-библиотеки (.so/JNI), а Flutter умеет
  звать C через **dart:ffi**.
- **Правильный путь:** обернуть sherpa-onnx C API через dart:ffi (модели GigaAM в ONNX).
  Это работа на 1 прототип, а не «невозможно».

### Провал 3: VOSK medium
- **Факт:** средней русской модели НЕТ (только 45 МБ и 1.8 ГБ). Не перепроверяем.
- Большая модель — отклонена пользователем (2 ГБ никто не качает). Закрыто.

## План перепроверки (по этапам, от лучшего к запасному)

### Прототип P1 (главный): sherpa-onnx + GigaAM CTC v2 через dart:ffi
- Шаги: взять Android-сборку sherpa-onnx (.so arm64-v8a), модели GigaAM ONNX, обёртка
  dart:ffi (offline recognizer), тест на vivo V2247: расшифровать тестовые записи Славана.
- Критерии: нет падений; WER заметно ниже VOSK (цель ≤15% на его записях); RAM ≤ 1 ГБ;
  скорость: час аудио ≤ 20 мин в фоне; размер модели ≤ 300 МБ.
- Готовый рецепт — из исследования Кими (промпт ИССЛЕДОВАНИЕ_3).

### Прототип P2 (параллельно, силами Итана): whisper.cpp из исходников
- Собрать whisper.cpp с `GGML_CPU_ALL_VARIANTS=ON` под arm64-v8a, минимальная обёртка
  (ffi или MethodChannel), модель ggml-base-q5_0 (~60 МБ), тест на vivo: проверить, что
  **SIGILL исчез** и модель грузится/расшифровывает.
- Цель прототипа: доказать/опровергнуть, что корень SIGILL был в сборке.

### Прототип P3 (запасной): ONNX Runtime Mobile + GigaAM без sherpa
- Если sherpa-обвязка окажется тяжёлой — zвать GigaAM напрямую через onnxruntime-android.
- Ставить в работу только если P1/P2 не дадут результата.
