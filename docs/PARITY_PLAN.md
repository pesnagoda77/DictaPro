# План: Дикта Android + Дикта iOS → одинаковое состояние

Важно понимать: у нас **один код** (Flutter) и **две сборки**. Значит «идентичность» — это не два продукта
писать заново, а закрыть **платформенные различия** и один раз проверить обе сборки по одному чек-листу.

## 1. Что различается по платформам (и почему)

| Тема | Android | iOS |
|---|---|---|
| Модель распознавания | отдельный **asset-pack Play** (222 МБ), при установке из магазина качается сам | **внутри приложения** (IPA 187 МБ) |
| Установка «просто APK» | базовый APK 50 МБ **без модели** — расшифровка не работает | dev-подпись по кабелю, модель внутри |
| Фон во время расшифровки | foreground-сервис + уведомление | аудиосессия + тишина + сторож (сделано) |
| Экран во время работы | не обязательно держать включённым | **не гаснет** пока идёт расшифровка (иначе iOS убивает процесс) |
| Оплата | Google Play Billing (подписки + пакеты) | StoreKit (те же ID) |
| Тест оплаты | лицензионные тестеры (деньги не списываются) | Sandbox-аккаунт Apple |
| Публикация | Play: внутренний/закрытый трек → продакшен | App Store Connect → TestFlight → ревью |
| Пуши (позже) | FCM (сервер + Firebase — готово) | APNs-ключ Apple → Firebase |

## 3. Android — что доделать

1. **Подписки в Play** (владелец): `sub_diary`, `sub_assistant`, `sub_unlimited` (+ годовые) и пакеты
   `pack_1h/10h/50h/200h`, `full_unlock`. → дождаться статуса «Активно».
2. **Лицензионные тестеры** (владелец) — чтобы проверить оплату без списания денег.
3. **Отправить релиз закрытого теста на проверку** (владелец, 1 клик) — сейчас черновик.
4. **Проверка на телефоне через Play** (я): установка из трека (модель приедет пакетом), расшифровка,
   покупка лицензионным тестером, лимиты.
5. «Жирный» APK с моделью — только для отладки, чтобы тестировать без Play (соберу по запросу).

## 4. iOS — что доделать

1. **App Store Connect**: создать приложение (`com.dictapro.app`) — владелец.
2. **Подписки и пакеты** с теми же ID — владелец.
3. **Sandbox-аккаунт** и вход им на телефоне (Настройки → App Store → Sandbox) — владелец.
4. **APNs-ключ** (для пушей, можно позже) — владелец.
5. **Прогон на iPhone** (я): расшифровка, фон, итоги онлайн/офлайн, покупка через sandbox.
6. Затем **TestFlight** → ревью Apple.

## 5. Как приводим к идентичному состоянию (проверка паритета)

Единый чек-лист, прогоняем **по очереди на Android и iPhone**, отмечая обе колонки. Пока не заполнены обе —
релиз не выпускаем.

| Проверка | Android | iOS |
|---|---|---|
| Запись 10 мин → расшифровка офлайн (авиарежим) | ☐ | ☐ |
| Длинная запись (>5 ч): предупреждение, не падает | ☐ | ☐ |
| Экран гаснет / сворачивание → расшифровка не теряется | ☐ | ☐ |
| Итоги локальные (офлайн) | ☐ | ☐ |
| Итоги онлайн (через наш воркер) | ☐ | ☐ |
| Экспорт TXT / PDF / HTML | ☐ | ☐ |
| Поиск, теги, переименование, удаление | ☐ | ☐ |
| Экран «Подписка»: тарифы и пакеты видны | ☐ | ☐ |
| Покупка тестовым аккаунтом → лимиты сняты | ☐ | ☐ |
| После покупки работает офлайн (льготный период) | ☐ | ☐ |
| Язык интерфейса ru и en — без «смеси» | ☐ | ☐ |
| Холодный старт в авиарежиме — не виснет | ☐ | ☐ |
| Версия и номер сборки совпадают | ☐ | ☐ |

**Правило паритета:** если функция работает на одной платформе и не работает на другой — это **блокер релиза**,
пока не исправлено или не задокументировано как платформенное ограничение (например, «на iOS экран не гаснет»).
